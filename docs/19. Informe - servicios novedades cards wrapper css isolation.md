# 19. Informe: servicios novedades cards wrapper css isolation

## Resumen ejecutivo

Este incremento previene una nueva colision de CSS global entre las paginas `/servicios` y `/novedades`. Ambas paginas compartian la clase generica `.cards-wrapper`, pero cada una necesitaba layouts distintos: `/servicios` usaba una grilla de 3 columnas en desktop, mientras `/novedades` usaba una grilla de 2 columnas con gaps y ancho propios.

Como el proyecto sigue usando CSS global, esa clase compartida podia producir comportamiento visual erratico segun la secuencia de navegacion client-side. La solucion fue aislar el wrapper de cards de cada pagina con clases especificas, manteniendo intactas las cards internas y el diseño esperado.

No se modifico backend, no se tocaron rutas, no se cambiaron textos publicos, no se altero el contrato de `/api/novedades`, no se agregaron dependencias y no se introdujo CSS Modules.

## Objetivo del incremento

- Aislar el wrapper de cards de `/servicios`.
- Aislar el wrapper de cards de `/novedades`.
- Evitar que ambas paginas compartan `.cards-wrapper`.
- Mantener el layout actual de cada pagina.
- Reducir el riesgo de colisiones CSS por navegacion client-side.
- Agregar una validacion simple para prevenir regresiones.

## Problema detectado

Despues de corregir la colision entre home y `/servicios`, quedaba otro patron similar:

- `/servicios` usaba `className="cards-wrapper"`;
- `/novedades` tambien usaba `className="cards-wrapper"`;
- `src/styles/servicios.css` definia `.cards-wrapper` con layout de 3 columnas;
- `src/styles/novedades.css` definia `.cards-wrapper` con layout de 2 columnas, gaps y ancho propios.

En una app con navegacion client-side y CSS global, esas reglas pueden convivir y afectarse segun que pagina se haya visitado antes.

El riesgo era que:

- `/servicios` perdiera su grilla esperada de 3/2/1 columnas;
- `/novedades` perdiera su grilla esperada de 2/1 columnas;
- el layout variara segun la secuencia de navegacion.

## Cambios implementados

### 1. Wrapper especifico para `/servicios`

Se actualizo:

- `src/app/servicios/page.js`

para reemplazar:

```jsx
className="cards-wrapper"
```

por:

```jsx
className="servicios-cards-wrapper"
```

Tambien se actualizo:

- `src/styles/servicios.css`

para mover las reglas de layout desde:

```css
.cards-wrapper
```

a:

```css
.servicios-cards-wrapper
```

incluyendo las media queries.

El layout esperado se mantiene:

- desktop: 3 columnas;
- tablet: 2 columnas;
- mobile: 1 columna.

### 2. Wrapper especifico para `/novedades`

Se actualizo:

- `src/app/novedades/page.js`

para reemplazar:

```jsx
className="cards-wrapper"
```

por:

```jsx
className="novedades-cards-wrapper"
```

Tambien se actualizo:

- `src/styles/novedades.css`

para mover las reglas de layout desde:

```css
.cards-wrapper
```

a:

```css
.novedades-cards-wrapper
```

incluyendo la media query.

El layout esperado se mantiene:

- desktop: 2 columnas;
- mobile: 1 columna.

### 3. Cards internas sin cambios

No se modificaron las clases internas de las cards:

- `/servicios` conserva `.service-card`;
- `/novedades` conserva `.novedad-card`.

El cambio se limito al wrapper que generaba colision.

### 4. Validacion estructural reforzada

Se actualizo:

- `scripts/validate-frontend-structure.mjs`

para validar:

- que `/servicios` no use `className="cards-wrapper"`;
- que `/novedades` no use `className="cards-wrapper"`;
- que `/servicios` use `servicios-cards-wrapper`;
- que `/novedades` use `novedades-cards-wrapper`;
- que `src/styles/servicios.css` no defina `.cards-wrapper`;
- que `src/styles/novedades.css` no defina `.cards-wrapper`;
- que ambos CSS tengan sus selectores especificos.

## Validacion manual recomendada

Como el cambio es visual, conviene revisar en navegador:

- abrir `/servicios` directamente;
- abrir `/novedades` directamente;
- navegar `/servicios -> /novedades -> /servicios`;
- navegar `/novedades -> /servicios -> /novedades`;
- confirmar layouts en desktop, tablet y mobile.

## Impacto tecnico

- `/servicios` y `/novedades` ya no comparten `.cards-wrapper`.
- Cada pagina conserva su layout con un wrapper propio.
- Se reduce el riesgo de comportamiento visual dependiente de navegacion previa.
- No se altera el contrato publico de novedades.
- No cambia el diseño de las cards internas.

## Riesgos remanentes

### 1. CSS global sigue existiendo

El proyecto sigue usando CSS global. Este incremento elimina una colision concreta, pero no evita que futuras clases genericas puedan generar problemas similares.

### 2. Validacion visual no automatizada

La validacion estructural comprueba nombres de clases y selectores, pero no verifica pixeles, layouts reales ni estados responsive. La revision visual sigue siendo necesaria.

### 3. Sin CSS Modules en este paso

No se introdujo CSS Modules ni una estrategia general de scoping para mantener el cambio pequeno y controlado.

## Conclusion

`servicios novedades cards wrapper css isolation` elimina una clase global compartida entre `/servicios` y `/novedades` que podia producir colisiones de layout. Cada pagina ahora tiene su wrapper especifico y conserva su grilla esperada, con un guardrail estructural para evitar regresiones.
