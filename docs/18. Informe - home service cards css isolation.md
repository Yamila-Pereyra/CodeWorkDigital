# 18. Informe: home service cards css isolation

## Resumen ejecutivo

Este incremento corrige el comportamiento erratico de hover y legibilidad de texto en las cards de servicios del home. El problema venia de una colision de CSS global: tanto el home como la pagina `/servicios` usaban la clase `.service-card`, y sus estilos podian afectarse segun la secuencia de navegacion client-side.

La solucion fue aislar las cards del home con clases especificas y fijar explicitamente los colores de texto en estado normal y hover. El cambio mantiene el diseño actual lo mas parecido posible y no modifica la pagina `/servicios`.

No se modifico backend, no se tocaron rutas, no se agregaron dependencias, no se cambiaron textos publicos y no se introdujo CSS Modules.

## Objetivo del incremento

- Aislar las cards de servicios del home para que no dependan de `.service-card`.
- Evitar que estilos de `/servicios` afecten visualmente al home.
- Estabilizar el color de texto normal y hover en las cards del home.
- Mantener el diseño actual con cambios minimos.
- No modificar el comportamiento visual de `/servicios`.
- Agregar una validacion simple para prevenir regresiones.

## Problema detectado

El home usaba:

```jsx
<section className="services">
  <div className="service-card">
```

La pagina `/servicios` tambien usaba:

```jsx
<div className="service-card">
```

Al mismo tiempo:

- `src/app/home1.css` definia reglas para `.service-card`;
- `src/styles/servicios.css` definia reglas para `.service-card`;
- `src/styles/globals.css` tambien definia estilos globales para textos como `h3` y `p`.

Como los estilos son globales, la navegacion client-side podia dejar cargadas reglas de `/servicios` que afectaran las cards del home. El sintoma observado era que el texto de las cards podia verse o no verse correctamente segun la ruta visitada previamente.

## Cambios implementados

### 1. Clases especificas para el home

Se actualizo:

- `src/app/page.js`

para reemplazar:

```jsx
className="services"
className="service-card"
```

por:

```jsx
className="home-services"
className="home-service-card"
```

Con esto, el home deja de depender de la clase global `.service-card`.

### 2. CSS del home actualizado

Se actualizo:

- `src/app/home1.css`

para mover las reglas del home desde:

```css
.services
.service-card
```

a:

```css
.home-services
.home-service-card
```

Tambien se actualizaron las reglas responsive asociadas para conservar el comportamiento visual existente.

### 3. Colores de texto explicitos

Se agregaron reglas especificas para estabilizar legibilidad:

```css
.home-service-card h3,
.home-service-card p
```

y:

```css
.home-service-card:hover h3,
.home-service-card:hover p
```

Estado normal:

- texto en `#d49494`

Estado hover:

- texto en `#ffffff`

Esto evita depender de colores heredados desde reglas globales de `h3`, `p` o desde estilos de `/servicios`.

### 4. Pagina `/servicios` sin cambios

No se modifico:

- `src/styles/servicios.css`
- `src/app/servicios/page.js`

La pagina `/servicios` conserva su diseño y sus clases actuales.

### 5. Validacion estructural reforzada

Se actualizo:

- `scripts/validate-frontend-structure.mjs`

para validar:

- que el home no vuelva a usar `className="service-card"`;
- que el home use `home-services`;
- que el home use `home-service-card`;
- que `home1.css` contenga selectores explicitos para texto normal y hover:

```css
.home-service-card h3
.home-service-card p
.home-service-card:hover h3
.home-service-card:hover p
```

## Validacion manual recomendada

Aunque el build y los gates pasaron, este cambio es visual. Conviene verificar en navegador:

- abrir `/` directamente y revisar las cards del home;
- navegar `/servicios -> /` y confirmar que las cards del home se ven igual;
- navegar `/ -> /servicios -> /contacto -> /` y confirmar que el hover del home se mantiene estable;
- revisar que `/servicios` conserve su diseño.

## Impacto tecnico

- El home deja de compartir `.service-card` con `/servicios`.
- Se reduce una colision concreta de CSS global.
- El texto de las cards del home queda estabilizado en estado normal y hover.
- La pagina `/servicios` no cambia.
- El cambio no introduce una nueva arquitectura de estilos, solo aísla el caso conflictivo.

## Riesgos remanentes

### 1. CSS global sigue existiendo

El proyecto sigue usando CSS global. Este incremento corrige una colision puntual entre home y `/servicios`, pero no elimina la posibilidad de futuras colisiones si otras paginas reutilizan clases genericas.

### 2. Sin CSS Modules en este paso

No se introdujo CSS Modules ni una estrategia global nueva de scoping para mantener el cambio acotado.

### 3. Validacion visual no automatizada

La validacion automatica comprueba clases y selectores esperados, pero no reemplaza una revision visual real del hover y contraste en navegador.

## Conclusion

`home service cards css isolation` corrige una colision de estilos globales que afectaba la legibilidad de las cards de servicios del home. Al usar clases especificas del home y fijar colores de texto normal/hover, el componente deja de depender de `.service-card` y queda protegido frente a estilos de `/servicios`.
