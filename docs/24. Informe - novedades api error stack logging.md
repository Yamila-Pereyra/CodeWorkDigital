# 24. Informe: novedades api error stack logging

## Resumen ejecutivo

Este incremento agrega logging explicito del error completo para diagnosticar el HTTP 500 observado en `GET /api/novedades`.

El backend levantaba correctamente con `npm start` desde `back`, pero al acceder a `/api/novedades` la consola solo mostraba el log resumido de Morgan:

```txt
GET /api/novedades 500 ...
```

Ese output no permite distinguir si la causa viene de MySQL, credenciales, tabla inexistente, query invalida u otro error interno.

La solucion agrega logging contextual en el error handler global, limitado a errores `>= 500` de `GET /api/novedades`. Se imprime el objeto de error completo, el mensaje y el stack trace cuando exista. La respuesta HTTP publica no cambia y no expone detalles internos al cliente.

No se modificaron queries, contratos de respuesta, variables `.env`, frontend, DB, migraciones, estilos ni estructura general del proyecto.

## Objetivo del incremento

- Diagnosticar el origen real del error 500 de `GET /api/novedades`.
- Imprimir en consola el error completo.
- Incluir contexto claro de ruta.
- Incluir `error.message`.
- Incluir `error.stack` cuando exista.
- Mantener la respuesta publica sin stack trace.
- No cambiar logica funcional ni contrato de novedades.
- No tocar configuracion de DB ni credenciales.
- No hacer refactors amplios.

## Problema detectado

La ruta:

```txt
GET /api/novedades
```

esta montada en:

- `back/routes/api.js`

y delega a:

- `back/controllers/apiController.js`

El controller usa `asyncHandler`, por lo que cualquier error termina en el error handler global de:

- `back/app.js`

Antes de este cambio, el error handler devolvia una respuesta JSON para rutas `/api`, pero no imprimia el stack trace del error especifico. El resultado era un 500 visible en consola solo como request fallida, sin causa tecnica.

## Cambios implementados

### 1. Deteccion especifica de `/api/novedades`

Se actualizo:

- `back/app.js`

Se agrego una funcion para identificar especificamente:

```txt
GET /api/novedades
```

```js
function isNovedadesApiRequest(req) {
  return req.method === "GET" && req.originalUrl === "/api/novedades";
}
```

### 2. Logging contextual del error

Se agrego:

```js
function logNovedadesApiError(error) {
  console.error("[GET /api/novedades] Error:", error);
  console.error("[GET /api/novedades] Message:", error && error.message);
  console.error("[GET /api/novedades] Stack:", error && error.stack);
}
```

Esto permite ver:

- el objeto de error completo;
- el mensaje puntual;
- el stack trace completo cuando exista.

### 3. Integracion en el error handler global

En el error handler global se agrego:

```js
if (status >= 500 && isNovedadesApiRequest(req)) {
  logNovedadesApiError(err);
}
```

El logging solo se ejecuta para errores internos de `GET /api/novedades`.

### 4. Respuesta publica sin cambios

La respuesta al cliente sigue pasando por el flujo existente:

```js
res.status(status).json({
  error: true,
  message: publicMessage,
});
```

En produccion, para errores 500, `publicMessage` sigue siendo:

```txt
Internal server error
```

No se expone stack trace al cliente.

## Riesgos remanentes

### 1. Logging acotado a una ruta

El logging detallado se agrego solo para `GET /api/novedades`. Otros endpoints siguen usando el comportamiento previo del error handler global.

### 2. No corrige la causa del 500

Este incremento no intenta corregir el error 500. Solo agrega visibilidad para identificar la causa real en la siguiente ejecucion.

### 3. Dependencias con avisos de auditoria

Al instalar dependencias del backend con `npm.cmd ci`, npm reporto vulnerabilidades existentes. No se corrigieron porque el objetivo era agregar logging diagnostico, no actualizar dependencias.

## Conclusion

`novedades api error stack logging` agrega visibilidad puntual para diagnosticar el 500 de `GET /api/novedades`. El backend ahora imprime error completo, mensaje y stack trace en consola, manteniendo intacta la respuesta publica y sin modificar queries, configuracion, frontend ni contrato legacy de novedades.
