# 05. Informe: repository operational hygiene and secrets handling

## Resumen ejecutivo

Este incremento mejora la higiene operativa del repositorio y corrige prácticas de versionado riesgosas relacionadas con secretos y artefactos generados. El foco estuvo en reforzar qué debe vivir como fuente de verdad en Git y qué debe quedar fuera del versionado activo.

## Objetivo del incremento

- Eliminar del versionado activo archivos sensibles y artefactos generados.
- Dejar una política mínima clara sobre qué sí y qué no debe commitearse.
- Mantener la reproducibilidad del proyecto mediante código fuente, lockfiles, archivos example y documentación.
- Reducir el riesgo de recaídas operativas sin tocar lógica de negocio.

## Riesgos operativos detectados

### 1. Archivo sensible versionado

`back/.env` seguía dentro del repositorio como archivo tracked.

Riesgo:

- exposición de secretos reales,
- confusión entre plantilla y configuración local,
- falsa idea de que el entorno debe compartirse por Git.

### 2. Dependencias instaladas versionadas

`back/node_modules` figuraba como parte del repo activo.

Riesgo:

- contaminación de la fuente de verdad,
- ruido masivo en diffs y revisiones,
- incremento artificial del tamaño del repo,
- acoplamiento innecesario a artefactos locales del entorno.

### 3. Metadata local de IDE versionada

`.idea/` seguía versionado.

Riesgo:

- ruido operativo,
- conflictos irrelevantes entre entornos de desarrollo,
- mezcla de configuración personal con fuente de verdad del proyecto.

### 4. Reglas incompletas en `.gitignore`

Las reglas existentes no cubrían de forma suficientemente clara:

- dependencias anidadas,
- artefactos de build anidados,
- metadata de IDE,
- env locales del backend.

### 5. Dependencia obsoleta

`md5` seguía declarada en `back/package.json` aunque ya no formaba parte del runtime activo tras el hardening anterior.

## Decisiones adoptadas

### 1. `back/.env` deja de ser fuente versionada

Se removió `back/.env` del versionado activo y se mantuvo `back/.env.example` como plantilla segura.

Esto separa correctamente:

- configuración real local,
- de configuración documentada y reproducible.

### 2. `back/node_modules` deja de formar parte del repo

Se removió `back/node_modules` del índice de Git.

No se trató como fuente de verdad, sino como artefacto generado localmente desde:

- `back/package.json`
- `back/package-lock.json`

### 3. `.idea/` deja de formar parte del repo

Se removió `.idea/` del versionado activo para evitar que metadata local del IDE siga compitiendo con el código fuente.

### 4. `.gitignore` reforzado

Se actualizó `.gitignore` para excluir explícitamente:

- `.env`
- `.env.*`
- `back/.env`
- `back/.env.*`
- `node_modules`
- `back/node_modules`
- `front/node_modules`
- `.next`
- variantes anidadas de `.next`
- logs
- `.idea/`

También se preservó la excepción necesaria para:

- `.env.example`
- `back/.env.example`

### 5. Validación preventiva de higiene

Se agregó:

- `scripts/validate-repo-hygiene.mjs`

con el objetivo de detectar si vuelven a aparecer en Git:

- env reales,
- `node_modules`,
- `.next`,
- logs,
- metadata de IDE.

Se expuso además:

- `npm run validate:repo-hygiene`

y se integró dentro del flujo de validación principal del repo.

### 6. Eliminación de dependencia obsoleta

Se removió `md5` de:

- `back/package.json`
- `back/package-lock.json`

porque ya no forma parte del runtime activo.

## Alcance implementado

Se actualizaron:

- `.gitignore`
- `README.md`
- `package.json`
- `back/package.json`
- `back/package-lock.json`

Se agregó:

- `scripts/validate-repo-hygiene.mjs`

Y se removieron del versionado activo:

- `back/.env`
- `back/node_modules`
- `.idea/`

## Política mínima de versionado dejada explícita

Debe vivir en el repo:

- código fuente
- configuración plantilla
- lockfiles
- scripts
- documentación

No debe vivir en el repo:

- secretos reales
- archivos `.env` locales
- `node_modules`
- artefactos de build
- logs
- metadata local del IDE

## Validación realizada

Se verificó:

- `npm.cmd run validate:repo-hygiene`
- `npm.cmd run validate` en `back`

Las validaciones pasaron correctamente.

## Riesgos remanentes y acción manual posterior

Hay una parte que no queda resuelta sólo con cambios en archivos:

### 1. Rotación de secretos

Si `back/.env` contenía credenciales reales ya compartidas en el historial, corresponde rotarlas fuera del código.

### 2. Limpieza histórica

Si el repositorio ya fue distribuido o publicado, sería recomendable evaluar limpieza del historial Git para remover rastros antiguos de secretos o artefactos impropios.

Este incremento mejora el estado actual del repo activo, pero no reescribe automáticamente la historia previa.

## Conclusión

`repository operational hygiene and secrets handling` mejora la separación entre fuente de verdad y artefactos del entorno, reduce exposición operativa innecesaria y deja una política mínima clara para sostener el repositorio en un estado más limpio, más reproducible y menos riesgoso.
